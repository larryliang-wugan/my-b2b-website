# WUGAN 新网站安装指南（零基础）

先在测试站操作，备份现有网站和数据库。使用 WordPress 6.6 或更新版、PHP 8.1 或更新版，并开启 HTTPS。

## 1. 安装新主题：从「外观」导入

1. 准备新版主题包 `wugan-studio.zip`。解压检查：应有 `wugan-studio/style.css`、模板等主题文件，不要上传整个项目压缩包。
2. 登录网站后台（域名后加 `/wp-admin/`）。选择 **外观 → 主题 → 安装主题 → 上传主题**（Appearance → Themes → Add New → Upload Theme）。
3. 选择 `wugan-studio.zip`，点击「现在安装」，安装完成后点击「启用」。这就是主题导入，不是「工具 → 导入」。
4. 进入 **外观 → Wugan setup**，点击 **Add starter content**，导入页面、产品和媒体。重复导入会保留已有同名内容。
5. 进入 **设置 → 阅读**，把首页显示设为静态页面，选择新建的 Home 页面。进入 **设置 → 固定链接**，选择文章名并保存。
6. 在 **页面** 中编辑页面正文；页面编辑下方的图片选择器可替换现有版面图片。在 **Products** 中编辑产品文字、特色图片、分类和图库。图库支持媒体库选择、排序和移除。

本次使用新主题 `wugan-studio`，不是旧版 `wugan-performance`。新主题为经典主题；不使用全站编辑器。已存在同名页面时，导入不会覆盖旧内容，应先在测试站核对对应页面。导航结构由主题模板提供。

## 2. 安装询盘插件

1. 把 `wugan-inquiries` 文件夹压缩为 `wugan-inquiries.zip`，确保内部路径是 `wugan-inquiries/wugan-inquiries.php`。
2. 后台进入 **插件 → 安装插件 → 上传插件**，上传压缩包，安装并启用「WUGAN Inquiries」。已有旧版时先备份，再使用 WordPress 的替换当前版本功能，不要同时启用两个副本。
3. 插件与主题分别安装；主题文件不能从插件菜单安装。

## 3. 建立联系页面

1. 导入后已有 Contact 和 Samples 页面，默认导航也已包含联系入口。
2. 联系页使用 `[wugan_inquiry]`，样品页使用 `[wugan_inquiry type="Samples"]`。访问 `/contact/`，确认能看到表单。
3. 产品按钮支持 `/contact/?product=underwear`、`/contact/?product=socks`、`/contact/?product=both` 及产品网址别名。产品详情页按钮会自动带入产品信息。
4. 如页面打不开，进入 **设置 → 固定链接**，选择「文章名」并保存，然后再次访问。WordPress 安装在子目录时，链接应包含该子目录。
5. 建立隐私政策页面，在 **设置 → 隐私** 中选择它。说明收集哪些资料、联系用途、保存期限及删除请求方式。上线前审核实际内容。
6. 在缓存插件、主机缓存和 CDN 中排除 `/contact/`、包含询盘表单的页面、带 `inquiry` 参数的请求及 `wp-admin/admin-post.php`；不要缓存 POST。否则 nonce 可能过期，提交确认也可能显示错误。

表单包含姓名、邮箱、公司、国家/地区、产品、选填数量、请求类型、留言和必须勾选的联系同意。数量可留空；填写时须为 1 至 100000000 的整数。产品预选只接受已知选项。

## 4. 邮件配置是上线必做项

插件收件人固定为 `sales@wugan.net`。必须先配置 SMTP 或可靠的事务邮件服务，并完成发件域名验证（服务商要求的 SPF、DKIM、DMARC）。安装 SMTP 插件后，按服务商说明填写服务器、端口、加密方式和认证资料。密码/API 密钥只保存在服务器配置或受保护的插件设置里，不要写进页面或主题。

先运行 SMTP 插件的测试邮件，再从网站用外部邮箱提交真实测试询盘，检查销售邮箱收件箱、垃圾箱及服务商投递日志。表单使用客户邮箱作为 Reply-To，发件人应由经过验证的 SMTP 配置决定。

提交后跳转到 `/contact/?inquiry=received`。只有带有效浏览器凭证的近期提交才显示「已保存」和询盘编号；凭证有效期 30 分钟。手工输入此网址不会伪造提交成功。禁用 Cookie、换浏览器或凭证过期后，页面会提示无法验证，不代表记录丢失。

邮件状态含义：

- `Accepted by mailer`：发送程序已接受请求，**不代表邮件已经送达收件箱**。
- `Failed`：记录已经保存，但通知发送失败。客户页面会明确提示通过邮箱联系，不需要重复提交。
- `Pending / interrupted`：发送流程可能中断，需要检查邮件日志。
- `Unknown`：旧数据或缺少状态，需要人工核实。

当前不自动重发邮件。管理员应每天查看后台记录，邮件失败时人工跟进；修复 SMTP 后重新进行端到端测试。

## 5. 附件和隐私

网站不接收文件上传，也不会把技术包放进公开媒体库。普通 WordPress uploads 目录通常可直接访问，无法仅靠「私密文章」保护附件。客户可把 PDF、JPG 或 PNG 技术包（建议合计不超过 10 MB）邮件发送到 `sales@wugan.net`，注明询盘编号；邮箱的实际附件限制以邮件服务商为准。此限制是邮件提交说明，网站不会检查邮件附件。

询盘保存为非公开 WordPress 记录，不提供公开查询或 REST 接口。后台查看、编辑、删除和 CSV 导出要求 `manage_options` 权限（通常为管理员）。数据库、备份和管理员账号仍需妥善保护；私密记录不是数据库加密。

## 6. 后台查看和导出

1. 管理员登录后台，打开 **WUGAN Inquiries**。
2. 列表中查看 Email status，点击记录查看全部字段、同意时间及邮件状态。
3. 点击 **Export all inquiries (CSV)**。导出需要已登录管理员权限和有效 nonce，包含全部非回收站询盘，不仅是当前筛选结果；旧版记录放在 Legacy record 列。
4. CSV 可用 Excel 打开，已防护常见公式注入。导出文件包含个人资料，不要上传到公开目录或随意转发。按实际隐私政策定期删除过期记录、回收站、导出文件和相应备份。

插件有 nonce、蜜罐和每个来源 IP 每 10 分钟最多 5 次有效提交的基础限流。限流不是完整反机器人服务；同一办公室可能共享额度。反向代理/CDN 环境需由主机正确提供来源 IP，插件不直接信任客户端的转发头。高流量站点应另外配置主机/WAF 限流。

## 7. CRM 尚未连接

本插件没有连接 OKKI 或其他 CRM，也没有自动同步成功的承诺。仅保留 `wugan_inquiry_created($post_id, $data)` 集成 hook，供后续独立适配器使用。接入前需要确认 CRM API、账号权限、字段映射、服务器端密钥、重试机制和以询盘 ID 为依据的去重策略；必须验证真实同步结果。

## 8. 上线前逐项测试

- 手机和电脑检查表单、产品预选、样品选项、隐私政策链接和成功页面。
- 提交正常询盘：确认后台私密记录、编号、字段、同意时间、邮件状态以及外部邮箱实际收件。
- 在测试站模拟 SMTP 失败：确认记录仍保存，页面明确提示通知失败，后台显示 Failed。
- 测试必填项缺失、非法邮箱、负数/小数数量、未知产品、未勾选同意、蜜罐、过期 nonce、超次数提交和文件上传请求均被拒绝。
- 使用普通编辑者及未登录浏览器确认无法读取询盘或导出 CSV；管理员导出检查中文、逗号、换行及以 `=` 开头的内容。
- 手工访问成功网址及清除 Cookie 后重试，确认不会虚报成功；确认缓存排除规则生效。

代码检查不能替代真实 WordPress、SMTP 与浏览器测试。未完成以上验证前，不要把网站标记为已具备可靠收件或 CRM 同步能力。
