# Deployment and operations

Use a Node.js 24 host with persistent disk, or the provided Dockerfile. Docker packaging is provided but has not been executed in this cloud environment. Static-only hosting cannot run the database, administration or inquiry endpoints.

1. Deploy the repository, run `npm ci --omit=dev` and `npm run build`.
2. Set NODE_ENV=production, APP_ORIGIN=https://wugan.net and PORT=3000. Put HTTPS in front of the application; keep the backend port private. Redirect www to the canonical domain. Set DNS at the domain provider to the chosen host.
3. Persist DATA_DIR (database, WAL and private uploads) and `/app/public/media` (uploaded and bundled product images). For non-Docker hosting use the corresponding repository paths. Do not overwrite these directories on redeploy. A single application instance is supported; do not horizontally replicate a local SQLite file.
4. Provision ADMIN_USERNAME and a strong ADMIN_PASSWORD (at least 14 characters) through secure host environment settings. Run `npm run admin:create`, then remove ADMIN_PASSWORD from the long-running application environment. This command resets the selected account password and invalidates all sessions. No public registration or default password exists.
5. Configure SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD and SMTP_FROM from the actual mailbox provider. Port 465 uses TLS; other ports require STARTTLS. INQUIRY_TO defaults to sales@wugan.com. Use the provider's application password when required. SMTP needs raw credentials in the host's secure environment, not an HTTPS proxy placeholder. Configure SPF/DKIM/DMARC according to that provider.
6. Start `npm start`. Check `/health`, public pages and admin login over HTTPS. Submit a real inquiry and attachment, verify it appears in the dashboard AND reaches sales@wugan.com, then verify Reply goes to the buyer. Failed/unconfigured notification remains visible in admin and can be retried. A submission success only confirms database persistence.
7. Schedule `npm run backup` daily and copy backups to restricted off-host storage. A backup contains wugan.sqlite, uploads/ and media/. To restore, stop the application, preserve the existing data, restore the database and directories into the matching paths, ensure the node user owns them, then restart and check an inquiry plus attachment. Do not restore over a running SQLite connection. Backups contain personal customer information.
8. Set retention and deletion procedures for inquiries and backups before launch. Restrict access to staff who need it. Privacy and business terms are draft operational copy for owner review, not jurisdiction-specific legal advice.

Cloud testing covers local HTTP, database, authorization, attachments, product/article editing, mocked email outcomes and responsive browser behavior. Public DNS/TLS, external SMTP receipt, Docker execution, off-site backup and production monitoring remain deployment tasks. No external buyer email is sent by automated tests.
